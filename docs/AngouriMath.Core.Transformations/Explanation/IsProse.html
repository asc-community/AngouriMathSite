IsProse​(System.​String)

 Method (no overloads)

Summary

Whether a rule's name is a phrase in English, rather than a rendered pattern.

Remarks

The distinction is real and this is not a heuristic about it. A rule written as
data is named by whoever wrote it, in words:
dividing-by-a-quotient-multiplies-by-its-reciprocal. A rule read off a
switch is named by RuleRegistryGenerator, which has no words to use and
names the arm by its own pattern:
Divf(Sinf(var any1), Cosf(var any1a)) when any1 == any1a. The two are told apart
exactly, by whether the name is lower-case letters and hyphens — a rendered pattern has
capitals, brackets and spaces, and cannot be mistaken for one.
 It matters because the first version of this rendered every name as a clause, and
produced "Divf(Sinf(var any1), Cosf(var any1a)) when any1 == any1a, so sin(x) /
cos(x) becomes tan(x)" — a sentence that quotes a matcher at the reader, which the
remark on Sentence(AngouriMath.Core.Transformations.RewriteRuleSet,AngouriMath.Core.Transformations.RewriteRule,AngouriMath.Entity,AngouriMath.Entity) says not to do while doing it. A name that is not prose
is not made into prose here; the sentence falls back to the identity, and then to naming
the set.
